Personal Light Novel Reader (iOS Native)

1. Mục Tiêu (Overview)
------------------------------------------------------------------------
Bảo đảm tốc độ tải dữ liệu tức thời (<0.5 giây) khi người dùng mở ứng dụng, lưu trữ cục bộ (offline-first) mọi thông tin truyện, và có cơ chế dọn dẹp bộ nhớ đệm (Cache) thông minh để không làm đầy dung lượng thiết bị của người dùng (đặc biệt khi tải nhiều file âm thanh TTS).

2. Kiến Trúc Database (SwiftData)
------------------------------------------------------------------------
Từ iOS 17, `SwiftData` được sử dụng thay thế cho `CoreData` để tận dụng cú pháp Declarative của Swift, an toàn kiểu dữ liệu (Type-safe), và tích hợp hoàn hảo với SwiftUI thông qua macro `@Model` và `@Query`.

Lược đồ dữ liệu cốt lõi (Schema):
```swift
@Model
final class Novel {
    @Attribute(.unique) var id: String // ID từ Google Drive
    var title: String
    var author: String?
    var coverURL: String?
    var lastModified: Date
    @Relationship(deleteRule: .cascade, inverse: \Chapter.novel)
    var chapters: [Chapter]
    var syncStatus: Int // 0: Synced, 1: Pending
}

@Model
final class Chapter {
    @Attribute(.unique) var id: String
    var title: String
    var content: String // Nội dung text hoặc JSON
    var readingProgress: Float // 0.0 -> 1.0
    var lastReadAt: Date?
    var novel: Novel?
    @Relationship(deleteRule: .cascade) var bookmarks: [Bookmark]
}

@Model
final class Bookmark {
    var id: UUID
    var textSnippet: String // Trích đoạn ngắn để hiển thị UI
    var exactPosition: Int // Index trong chuỗi
    var note: String?
    var createdAt: Date
}
```

3. Chiến lược Lưu trữ Bộ nhớ đệm (Caching Strategy)
------------------------------------------------------------------------
Hệ thống sử dụng bộ đệm đa tầng (Multi-level Caching):
- **Tier 1: In-Memory Cache (RAM)**:
  Sử dụng `NSCache` để lưu các chương truyện đang đọc hiện tại. Lợi ích: Render văn bản khổng lồ mà không cần truy xuất ổ cứng, tăng độ mượt khi cuộn. Tự động bị hệ điều hành xóa khi Memory Warning.
  
- **Tier 2: Disk Cache (SSD) cho Audio TTS & Ảnh Bìa**:
  - TTS sinh ra rất nhiều file `.mp3` hoặc `.wav`.
  - Thay vì lưu vào CSDL, ta lưu dạng File System tại thư mục `Caches/TTS_Audio`.
  - Giới hạn dung lượng (Ví dụ: 500 MB).

4. Thuật toán Dọn dẹp Cache (LRU Eviction Policy)
------------------------------------------------------------------------
Để tránh việc ứng dụng phình to lên nhiều Gigabyte, một Background Task sẽ chạy thuật toán LRU (Least Recently Used) để xóa các file âm thanh cũ:
1. Duyệt thư mục `Caches/TTS_Audio`.
2. Lấy metadata của các file (thuộc tính `NSFileModificationDate` hoặc `NSFileCreationDate`).
3. Nếu tổng dung lượng > 500MB, sắp xếp file theo thời gian truy cập cũ nhất.
4. Xóa dần các file cũ nhất cho đến khi tổng dung lượng giảm xuống còn 300MB.

5. Migration và Data Integrity (Bảo toàn dữ liệu)
------------------------------------------------------------------------
- Quản lý phiên bản (Schema Versioning): Sử dụng `SchemaMigrationPlan` của SwiftData để định nghĩa sự thay đổi giữa v1, v2, v3...
- Khi có bản cập nhật ứng dụng thay đổi cấu trúc DB (thêm cột mới, đổi kiểu dữ liệu), `MigrationPlan` sẽ chạy hàm custom mapping để chuyển đổi dữ liệu người dùng mà không làm mất sách hay bookmark.
- Cơ chế Backup: Không cần thiết do dữ liệu gốc (Single Source of Truth) đã được sao lưu trên hệ sinh thái Google Docs/Drive của người dùng.
